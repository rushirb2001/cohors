## Where this came from

Started as a request to optimize the user's personal VS Code setup (settings,
keybindings, extensions). That produced a custom "Launch pad" dashboard
extension, which went through several rejected designs (gradients, a naive
2-column card grid, a walkthrough that auto-collapsed) before landing on the
current shell. Partway through, the user decided this was worth building as a
**real product**, not just personal config, and Principia was born as a
separate, publishable repo: https://github.com/rushirb2001/principia

Key pivot, stated explicitly by the user: **"I don't need to manually enter
things... agent-configured... publishable... combination of extension + Claude
Code plugin + skill, so I can use it on other devices."** That sentence is
the whole architecture. Everything under `spec/`, `prompts/`, `mcp/`, and
`skills/`/`agents/` exists because of it.

## Bugs found and fixed this session (worth knowing so they don't recur)

1. **CSS class collision**: introduced `.side` for a row-action slot without
   checking the app's own sidebar was already `<aside class="side">`. Same
   selector, later rule won, sidebar collapsed to a 20px sliver. Renamed the
   row-slot usage to `.rslot`. **Lesson: grep for a class name before
   introducing it in a file this size.**
2. **2-column card grid** auto-paired cards strictly by DOM order; a
   grid row sizes to its tallest member, so a short card next to a tall one
   left a large dead gap. Replaced with an explicit `.main`/`.rail` split —
   no card's height is ever coupled to another's.
3. **`status` mode in the CLI skipped every step's `run()`**, including the
   three steps whose only job is populating shared state (which runners are
   installed, where the contract lives) that *later* steps' prerequisite
   checks read. So `status` always reported downstream steps unavailable
   regardless of truth. Fixed by marking those three `readonly: true` so they
   still execute (no side effects) even in status mode.
3. **Heading text char-by-char wrap**: a blanket `overflow-wrap: anywhere`
   meant for unpredictable content (repo names, paths) was also hitting
   short static headings, which broke visibly once a flex/grid parent
   squeezed their container. Scoped the aggressive wrap rule off headings.
4. **Command injection** (real, caught by an automated security review, not
   self-caught): a repo's committed `.principia/repo.json` could inject shell
   metacharacters through an agent id into a spawned terminal command. Fixed
   with proper `shq()` single-quote escaping plus path-traversal containment
   checks on `agents[].file`. Verified with a deliberately hostile config.

## Known limitations, stated explicitly rather than left implicit

- **CLI is not npm-published**, and can't be trivially: if `cli/` were
  published standalone, the contract files (`spec/`, `prompts/`,
  `scripts/validate.js`) live in the *parent* directory and would not be
  included. `principia init` currently only works from a checkout of this
  repo (`npm install -g cli/`, or the global install already done on this
  machine). Publishing for real needs either bundling those files into
  `cli/` at pack time, or a separate `principia-contract` package.
- **VS Code extension install is a dev symlink**, not a real marketplace
  install (`code --install-extension`), since the extension isn't published.
  `principia init`'s "vscode-extension" step is honest about this in its
  label.
- **Makefile target detection** (in `extension/src/discovery.js`) is naive —
  picks up the first few targets regardless of whether they're meaningful
  (e.g. `make default`, `make main` on `sushrutalgs-ios`). A repo's own
  `.principia/repo.json` is meant to override this, but the heuristic itself
  could be tightened.
- **The MCP server's validation logic is a hand-kept duplicate** of
  `scripts/validate.js`'s rules (in `mcp/src/lib.js`), not a shared import.
  They were cross-checked once (an MCP write's output was independently
  re-validated by the CLI validator and agreed), but a future schema change
  has to be applied in both places.
- Never tested: the extension's behavior on a second machine with zero prior
  Principia state (the actual "empty install" experience). Only tested
  against the dev machine's real 16 discovered repos.
